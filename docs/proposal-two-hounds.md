# デジタルコンテンツ企画書「光と影の猟犬」

チーム26：木澤・村松・中野・森井  
作成日：2026年10月22日

## 1．作品の目的

本作品は、光と影で性質の異なる二匹の猟犬を操作し、盤面の明るさを変えながら攻略する、一人用のターン制戦術ゲームである。ユーザーに「盤面を読み、自分で有利な状況を作り、二匹の連携で突破する体験」を提供する。

対象は、パズルや戦略ゲームが好きで、位置取りや行動順を考えることを楽しみたいユーザーである。素早い操作を要求せず、敵の予告や明るさを確認してから行動できるようにする。PCのブラウザでのプレイを基本とし、画面配置を調整してスマートフォンからの操作にも対応する。

目的を達成するため、以下のように体験と仕組みを結び付ける。

| 提供したい体験 | 着眼点・仕組み | その仕組みが目的につながる理由 |
| --- | --- | --- |
| 自分の判断で状況を改善する | 灯火や遮蔽物を操作して明暗を変える | 既にある安全地帯を選ぶだけでなく、移動や攻撃に適した場所を自分で作れる。 |
| 二匹を連携させて突破する | 二匹の得意な明るさを逆にし、行動順を選べるようにする | 一匹のための明暗操作がもう一匹には不利になる場合があり、両者の位置と順番を合わせる必要が生まれる。 |
| 情報を基に作戦を考える | 敵の次の行動を事前に表示する | 予告された危険に対し、移動、攻撃、明暗操作、遮蔽のどれを使うか比較できる。 |

これらは設計上の狙いである。狙いが実際に伝わるかは、制作後半の試遊で、判断の理由と操作に迷った箇所を確認する。

## 2．作品構想

### 基本のアイディア

光の猟犬は明るい場所、影の猟犬は暗い場所で有利になる。プレイヤーは一人で二匹を操作し、敵の配置だけでなく、灯火と遮蔽物によって生まれる明暗を利用してステージの目標を達成する。

盤面はマスで区切り、見た目は斜め上から立体模型を眺めるような3Dとする。ゲーム上の移動・射程・明るさの判定は、2Dのマス座標で管理する。

| 要素 | 基本的な役割 | プレイヤーが考えること |
| --- | --- | --- |
| 光の猟犬 | 明所で移動・攻撃が有利。灯火を移動して周囲を照らす。 | 自分を強くする光をどこに置くか。影の猟犬の通り道を残せるか。 |
| 影の猟犬 | 暗所で移動・攻撃・回避が有利。遮蔽物や影の技で暗所を作る。 | 影をどこにつなぐか。光の猟犬を不利にせず攻撃位置へ進めるか。 |
| 灯火 | 周囲のマスを照らす。光源からの距離で明るさが変わる。 | どの範囲を照らし、どこに暗さを残すか。 |
| 遮蔽物 | 光や射線を遮り、背後に暗い場所を作る。移動も妨げる。 | 身を守る効果と、通路をふさぐ不利益をどう両立するか。 |
| 敵の予告 | 次の攻撃範囲や移動先を表示する。 | 二匹の行動で危険を避けるか、敵の実行条件を崩すか。 |

### 一ラウンドの流れ

```text
敵の行動予告と盤面を確認
            ↓
光から／影から、行動順を選択
            ↓
一匹目：移動 → 技を一つ使用
            ↓
二匹目：変化した盤面で移動 → 技を一つ使用
            ↓
敵：予告した行動を実行
            ↓
目標達成・失敗を判定 → 次のラウンド
```

移動と技はそれぞれ省略できる。敵は予告後に狙い直さず、遮蔽物や明暗の変化で実行条件を満たせなくなった攻撃は中止する。このルールにより、行動前に立てた作戦と、その結果を対応させられる。

### 攻略の具体例

暗所では防御が高くなる「影鎧兵」がいる場面を考える。

| 手順 | 操作と盤面の変化 | 判断の意味 |
| --- | --- | --- |
| ① 状況確認 | 影鎧兵は暗所におり、そのまま攻撃すると防御でダメージが減る。 | 攻撃する前に、敵の防御条件を崩す必要がある。 |
| ② 光を先に行動 | 光の猟犬が灯火を移し、敵のマスを暗所から薄明へ変える。 | 敵の防御を下げ、後続の攻撃を通しやすくする。 |
| ③ 影が攻撃 | 影の猟犬は自分の足元に暗さを残し、隣接する敵を攻撃する。 | 敵だけを照らし、自分の暗所での攻撃補正を利用する。 |
| ④ 照らしすぎを比較 | 敵のマスを最も強い光にすると、影の通常攻撃は使えなくなる。 | 「明るければよい」ではなく、二匹に適した照らし方を選ぶ。 |

この例では、敵への照明と味方の足元の暗さが別々の意味を持つ。さらに影が先に行動すると、敵の防御を下げる前に攻撃することになるため、同じ二匹・同じ技でも行動順によって結果が変わる。

また、直線射撃を予告する敵には、射線上に遮蔽物を置く、または発射元を暗くして射撃条件を崩す対処を用意する。攻撃して敵を倒す以外にも、盤面を変えて危険を防ぐ選択肢を作る。

## 3．作品の独創的な点

本作品の特徴は、光と影の操作を、二匹の異なる能力、行動順、敵の予告への対処に結び付ける点にある。既存作品との比較を以下に示す。

| 比較作品 | 既存作品の仕組み | 本作品との違い・目指す利点 |
| --- | --- | --- |
| Shadow Puppeteer | 少年とその影が協力し、光を操作してパズルを解く。一人プレイとローカル協力プレイに対応する。[1] | 本作品は一人が二匹を順番に動かす。光の操作をマスごとの移動・攻撃条件に結び付け、連携を操作の同時性よりも行動順の判断で表現する。 |
| Contrast | 3D空間と2Dの影の世界を行き来し、光源や物体を操作して影を変えるパズル・プラットフォーム作品。[2] | 本作品では二匹と敵が同じマス盤面を共有する。明暗の変更を、移動だけでなく味方の能力と敵の攻撃条件にも反映し、一つの操作を攻守の両方に使う。 |
| Into the Breach | 敵の攻撃予告を読み、対処を考えるターン制戦術ゲーム。[3] | 本作品では予告への対処に明暗操作を加える。同じ場所でも光の変化で有利不利が変わるため、位置と明るさを合わせて考える構造を目指す。 |

これらの比較から、本作品では「明るさという共通の盤面情報が、二匹には異なる意味を持つ」ことを中心に設計する。全体を明るくする、影だけを増やすといった一方向の改善ではなく、場所ごとの役割分担を考えられる点を企画上の強みとする。

## 4．詳細

### 4.1 具体的なソフトウェアの中身

| 項目 | 制作する内容 |
| --- | --- |
| 盤面 | 横14×縦8マスを基本とする。上下左右に移動し、キャラクターや遮蔽物のあるマスは通り抜けない。 |
| 明るさ | 0～4の五段階。光源との距離、遮蔽物、明暗を変える技から計算する。 |
| 移動 | 犬ごとの移動予算に対し、経路の明るさに応じた進入コストを合計して移動可能範囲を求める。光は明所、影は暗所を進みやすくする。影は最も強い光のマスへ進入できない。 |
| 技 | 通常攻撃、防御、灯火の移動、遮蔽物の設置、直線状の明暗変更を基本とする。明暗変更の技は直接ダメージではなく、次の行動の条件を変える。 |
| 使用回数の制約 | 明暗変更の強力な技や遮蔽物設置には、時間経過で回復する共通チャージを使う。二匹のどちらに使うかも判断する。 |
| 敵 | 接近して攻撃する敵、直線射撃を行う敵、暗所で防御が高くなる敵を基本とする。次の行動を事前に表示する。 |
| ステージ目標 | 敵の討伐を基本に、対象物を回収して帰還する課題を設ける。二匹とも戦闘不能になると失敗する。 |
| 進行・保存 | ステージのクリア記録と設定をブラウザに保存し、次の課題を選べるようにする。 |
| 導入 | 最初は二匹の操作、次に灯火、次に遮蔽物と敵予告を教え、最後に組み合わせて解く構成とする。 |

数値の細部は調整対象とし、企画段階では「二匹の適性の違い」「明暗操作」「予告と結果の一致」を維持する。影の現在地が強い光になった場合の退避処理など、例外も試作段階で検証する。退避先がない配置は基本ステージで発生させない方針とし、例外処理は11月6日の試作確認までに確定する。

### 4.2 画面設計・UI設計

```text
タイトル → ステージ選択・目標確認 → 戦闘 → リザルト
                    ↑                         │
                    └──── 次の挑戦・再挑戦 ──┘
```

戦闘画面は次の構成とする。

```text
┌───────────────────────────────────────┐
│ 目標 ／ ラウンド ／ 手番 ／ 共通チャージ             │
├──────────────────────┬────────────────┤
│                      │ 光・影のHPと現在地の明るさ │
│     斜め上からの3D盤面  │ 行動順：光から／影から    │
│                      │ 移動の確定・省略         │
│ 灯火・遮蔽物・二匹・敵   │ 技の選択と対象           │
│ 移動範囲・経路・敵予告   │ 実行後の予測／操作説明    │
└──────────────────────┴────────────────┘
```

PC横長画面では盤面の横、スマートフォンの縦画面では盤面の下に操作パネルを配置する。

- 移動先を選ぶと経路と消費コストを表示し、確定前に確認できるようにする。
- 明るさは床の色に加えて数値でも確認できるようにする。
- 敵の攻撃予告は斜線、移動予告は矢印とし、色だけに頼らず区別する。
- 灯火や技の対象を選ぶと、実行後の明るさと敵予告への影響を表示する。
- 使えない技には「対象が強い光の中にいる」などの理由を示す。
- 影の猟犬には選択枠や輪郭表示を付け、暗所でも操作対象を見失わないようにする。

### 4.3 使用する言語・ライブラリなど

| 技術 | 用途・選定理由 |
| --- | --- |
| TypeScript／JavaScript | 明るさ、移動、戦闘、進行を実装する。新規ルールはTypeScriptとし、状態や引数の誤りを型で確認する。既存JavaScriptは段階的に整理する。 |
| HTML／CSS | ボタン、説明、HPなどのUIと、画面幅に応じた配置を実装する。 |
| Three.js／WebGL | 犬、敵、地形、照明を3D描画する。導入済みの描画基盤を利用する。 |
| Vite／npm | 開発用サーバーと配布用ビルドを用意する。共有したロックファイルとnpm ciで環境をそろえる。 |
| localStorage | クリア記録と設定をブラウザ内に保存する。 |
| Web Audio API | 操作・移動・攻撃の音と音量設定を扱う。 |
| Vitest／Playwright | ルールの自動検証と、ブラウザでの画面遷移・入力・保存の検証に使う。 |

構成は「ゲームルール」「画面操作」「描画」「音声」「保存」に分ける。例えば明るさによる能力や敵の命中判定はゲームルール側に集約し、画面表示と実際の処理が同じ判定を参照する。公開時はビルドしたファイルをHTTPS対応の静的ホスティングへ配置する。

## 5．制作計画

### 5.1 完成範囲と制作上の難易度

必須範囲は、二匹の操作、五段階の明るさ、灯火と遮蔽物、敵予告、討伐・回収の目標、画面遷移、クリア記録の保存とする。まず導入・明暗操作・遮蔽・総合課題を含む代表ステージを4件以上完成させる。残りの既存ステージは、その完成後に調整・追加する。

制作の主な課題は、光の変化を移動・攻撃・敵予告のすべてへ矛盾なく反映し、その関係を画面上で分かるようにすることである。各ルールを実装するだけでなく、二匹の連携として成立させる統合作業を制作の中心に置く。

一方、猟犬は二匹、基本マップは固定サイズ、操作はターン制とし、既存の試作とThree.js基盤を利用する。扱うキャラクター数やステージ数を抑え、ルールの組合せとUIの完成度に作業を集中する。

| 村松 | 明るさ・マップ・経路探索の実装 | 光源と遮蔽、移動可能範囲、明暗変更、退避処理。照らし方と経路コストの境界条件を確認する。 |

### 5.4 完成確認の方法

完成条件は、初めて遊ぶ人が案内に沿って二匹を操作し、明暗を変えて代表ステージをクリアし、再読込後もクリア記録が残ることである。

試遊では、操作が止まった箇所と説明を求められた場面を記録する。プレイ後には「灯火をその位置に動かした理由」「二匹の行動順を選んだ理由」を聞き、目的とした判断が伝わっているか確認する。

自動検証では明るさ、経路、手番、予告と命中、目標達成、保存を確認する。PC・スマートフォンの実機では、文字や盤面の見やすさ、タッチの選択位置、音声を別途確認する。外部素材を使う場合は出典とライセンスを記録する。これらは今後の確認計画であり、現時点で検証済みという意味ではない。
