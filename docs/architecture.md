# 技術方針・移行計画

## 判断

URLから遊ぶことを優先し、Webアプリとして開発する。HTMLは画面の構造として必要であり、単一HTMLにすべてを埋め込む構成から段階移行する。「会社と同じ唯一の構成」は存在しないため、この4人規模のゲームに必要な再現性・責務分離・検証・公開手順を基準にする。

## 技術要件

| 領域 | 選定・方針 | 状態 |
| --- | --- | --- |
| 開発・本番ビルド | Vite、npm、ロックファイル | 導入 |
| 言語 | TypeScript strict、新規ルールはDOMから独立 | 入口・能力定義のみ。既存JSは移行中 |
| 3D | Three.js、glTF/GLB、Blender制作モデルを目標 | Three.js、GLTFLoader、SkeletonUtilsでリグ付き狼GLBを導入。敵・装備は独自生成 |
| UI | HTML/CSS、意味のあるボタン、PC/タッチ対応 | 既存実装を分離 |
| テスト | Vitestによるルール検証、Playwrightで実ブラウザ操作 | 初期検証のみ |
| CI | GitHub Actionsでビルド・テスト | 設定追加。リモート実行は未確認 |
| 保存 | localStorage、将来はバージョン・検証・入出力の責務を分離 | 既存形式を保持 |
| 公開 | HTTPS静的ホスティングへdistを配置 | 公開先未設定 |

Reactやサーバー、DB、オンライン基盤は現行の要件から必須とは判断しない。フレームワークやファイル数を増やすことを品質指標にしない。

## 境界

最終的に`game`が状態と純粋なルールを管理し、`data`が技・クエストを定義する。`render`・`ui`・`audio`は状態を参照して表現し、プレイヤーの操作をコマンドとして返す。状態を変更する入口は一本にする。`storage`は検証・移行・読み書きを扱う。

今は`app/legacy-game.js`に統合処理が残る。大量の空ディレクトリを先に作らず、実際に責務を抽出するときにファイルを追加する。

## 次の実装順

1. 既存ゲームの基本操作・保存・4クエストの回帰検証を増やす。
2. セーブの書き出し・読み込みと不正値検証を導入する。
3. マップ、明るさ、移動、手番、戦闘、報酬をDOM非依存のTypeScriptへ抽出する。
4. Three.jsの描画アダプターを導入済み。整数のマスと描画の座標を分離。狼の外部GLB読込を導入済み。端末別品質設定は未導入。
5. リグ付きの犬モデル、歩行・攻撃・被弾、照明を順に改善する。外部素材のライセンスを記録する。
6. PC・縦スマホ・短い横画面で座標選択、操作、音声を確認し公開する。

各段階で遊べる状態を保ち、未完了の項目を実装済みと記載しない。

## 公開前の基準

五段階の能力、経路、退避、運び手の帰還と落下、報酬の一回付与、旧保存データ、演出中の連打・再挑戦を確認する。ブラウザ検証と実機の音声・タッチ確認を区別する。性能の目標値は実機計測後に決め、未計測のFPSを保証しない。

## 描画・モデルの更新

`src/render/three-world.ts`がカメラ・投影・マスの選択・照明・影・GPUバッファを管理する。既存のゲームからはcamera/project/pick/static/drawを呼び出す。動的な頂点バッファは容量を再利用し、静的ジオメトリの置換時には旧GPU資源を解放する。

`mesh-builder.js`はプリミティブ、`hound-model.js`は犬の体型・関節・専用装備、`kennel-scene.js`は拠点の造形を扱う。犬はオリジナルの手続き生成モデルで、外部のリグ付きGLBやモーション素材は使用していない。

接地影はDirectionalLight、灯火と遮蔽物の遮蔽はマテリアル側のレイと箱の交差で処理する。点光源3個に各6面のシャドウマップを生成する構成を避ける。実機性能は未計測。

装備は`profile[kind].gear`を拠点へ、出発時コピーの`game.loadout[kind].gear`を戦場へ渡す。相棒プレビューの試着は保存・能力を変更しない。犬と装備の造形・工房のSVGイラストは今回のオリジナル実装。

## 装備と敵移動の境界

`game/equipment.ts`が8レシピ、段階解放、所有・着用・材料消費・明暗による効果・旧形式移行を定義する。`ui/forge.ts`が一覧・比較・操作を表示し、`render/hound-equipment.js`と`render/equipment-icon.ts`は同じIDから外観を選ぶ。ゲーム側は`equipmentBonus`の結果を参照し、UIで能力値を別計算しない。

`game/pathfinding.ts`は敵の一歩を決める幅優先探索。描画やDOMに依存せず、障害物・占有は呼び出し側から渡す。移動と攻撃を同じ手番で両方行わないルールは維持する。

## 固定予告と行動順

- `game/tactics.ts`: 敵の種類、防御、味方の対敵ダメージ、固定した予告の生成、現在の盤面で実行できる範囲の判定。
- `game/turn-order.ts`: 各犬が一回ずつ行動する管理と、戦闘不能・退避による一回省略。
- `game/tactics-stage.ts`: 育成と保存を変えずに試せる独立した戦術演習。

ラウンド開始時に予告の座標をコピーして固定する。敵手番で`planEnemies`を再実行しない。表示・選択先のプレビュー・実際の命中はすべて`assessPlan`を使う。遮蔽物で止まった場合、別のマスへの攻撃や経路変更に切り替えない。射撃は発射元の明るさ、ダメージは命中時の犬の明るさ・防御・回避で判定する。

プレイヤーは最初の移動または移動省略を確定する前に先手を選ぶ。その後は操作中の犬を変更しない。行動済みの犬を記録し、逆順でも各犬一回の制約を保つ。影の退避が行動前か後かによって、当該ラウンドまたは次ラウンドの一回省略として処理する。

## 相棒と特殊能力

`game/special-abilities.ts`が命名の正規化、静止ラウンドの集計、待ち伏せ補正、合体技の条件・範囲・基礎威力を定義する。`game/tactics.ts`は影縛り・ワープ・囮生成の固定予告と共通の実行判定も扱う。UIと演出はこれらの結果を参照する。名前はプロフィールの任意フィールド、能力の発動・静止・拘束は戦闘限りの状態とする。外部素材・依存の追加はない。

## 2026-10-19：図鑑の360度観察

図鑑に猟犬8体の外観・レア度・加入状態を追加。猟犬および遭遇済みの敵は「360°で見る」から専用表示を開く。未発見の敵は従来どおり未発見表示とする。左右のドラッグ／スワイプ、スライダー、左右回転ボタン、矢印キーで水平回転でき、向きを戻すボタンで初期方向に戻る。

## 2026-10-19：猟犬ごとの育成・攻撃技・ミッション通知

### 育成の入口と保存

拠点の施設は「仲間／ミッション／刻印／図鑑」。仲間の編成カードの「育成・装備」からレベル上げ、攻撃・体力訓練、調律、装備の作成・着脱を行う。調律専用画面と工房の独立入口は撤去。刻印抽選・装着は既存の刻印画面を維持する。

`game/hound-growth.ts`が個別のlevel/xp/power/guard/attunementをprofile.growth[猟犬ID]に管理する。初回移行では所持済みの各猟犬に従来の属性枠の育成値を引き継ぐ。移行後の新規加入はLv.1・EXP0・訓練0・調律なし。既存のprofile.light/shadowは装備コンテナとして維持し、育成値は選択した猟犬から投影する。保存キーlightShadowSave、装備・素材・通貨・名前・進行は維持。

本編報酬の経験値は出発時に選んだ二匹にだけ加算する。待機中の猟犬は成長しない。従来どおり次レベルに必要な経験値は現在レベル×3。固定演習・追加探索・対人戦は元の報酬規則のまま。

素材育成：次レベルまで上げる費用は現在レベルと同数の影の結晶。攻撃訓練は金属片2＋訓練回数×2で攻撃+1。体力訓練は影の結晶2＋訓練回数×2で最大HP+2。調律は第3節クリア後に無料変更。追撃＝攻撃+1、守護＝防御+1、なしに戻すことも可能。装備の所持・着用は光／影の属性枠共有を維持し、育成画面に明記する。

### 追加攻撃技

本編・通常の追加探索では、通常攻撃・明暗操作・防御・連携に加え、以下の1系統を各猟犬が使える。全て共通チャージ2を消費して技行動を終了する。敵だけを攻撃し味方は傷つけない。固定演習・固定試練と対戦／レイド専用盤の固定ルールは維持。

|技|猟犬|対象と効果|
|---|---|---|
|薙ぎ払う牙|黎明・アウル|隣接した方向の前方横3マス。通常攻撃相当の威力|
|貫く咆哮|ノクス・セレネ|縦横の直線3マスを貫通。攻撃+1|
|命喰らいの牙|宵・フェン|射程2の単体攻撃。ダメージを与えたら自身のHPを最大2回復|
|星火の炸裂|レグルス・イグニス|射程3の着弾点と隣接4マス。攻撃-1（最低1）|

`game/hound-skills.ts`が技の割当・対象範囲・攻撃値を定義。プレビューと発動は同じ計算を利用する。遮蔽物・低い壁・地形の射線を参照し、直線攻撃は壁で止まる。影の猟犬は最強光のマスを技の対象に含めない。新技は遮蔽物を壊さず、従来の通常攻撃で破壊する。技選択時に攻撃可能な敵を赤枠、狙った範囲を盤面に表示する。

### ミッション

拠点に独立したミッションボタンを置き、受取可能な未受取ミッションが1件以上ならアイコン右上に通知点を表示する。件数はボタンの読み上げラベルにも含める。受取後は共通ルールで件数を再計算し、全て受取済みなら点を消す。

## 2026-10-19：固定ヘッダー・独立ガチャ・敵の造形

- 仲間画面は固定したhub-fixed（見出し・閉じる・タブ・通知）とスクロールするhubContentに分割。PC・縦横画面で上部操作を維持する。育成や対戦の内容はスクロール領域内に表示。
- リザルトの「仲間を育てる」ボタンを削除。仲間の育成は拠点の「仲間」から行う。
- 猟犬召喚と刻印召喚を独立したガチャ画面（ui/gacha-hub.ts）へ統合。拠点の「ガチャ」から種類を切替。仲間の召喚タブと、施設タブの旧刻印画面を撤去。
- 猟犬の結果はgachaResultDialog、刻印の結果は既存のsigilRevealDialogで表示。結果から前回と同じ回数をもう一度引ける。回数・必要通貨を表示し、不足時はボタンを無効にする。刻印の交換結果は抽選ではないため再抽選ボタンを表示しない。
- 既存の排出率、星5保証、刻印保証、重複変換、指名交換、通貨、保存キーは維持。ゲームルールをUIへ複製せずroster.ts / expansion.tsの既存の抽選・付与処理を呼ぶ。抽選結果は表示前に保存する。
- 刻印の装着は仲間の育成画面へ移動。選択中の装備に対して所持刻印を付け外しでき、他装備で使用中の個数は既存socketSigilで検証する。
- enemy-detail.jsで傭兵の面頬・胸甲・肩甲・盾・刃・すね当て、ゴブリンの眉・鼻・牙・皮革・鉈、竜の鱗・翼膜・翼骨・歯・爪、喰らいの仮面・王冠・肋骨・光輪・外套を追加。竜の首・脚・尾は曲線に沿った関節と筋肉の量感へ変更。光影の配色と陰陽の装飾を使い分ける。
- 自作の手続き生成を継続し、外部モデル・素材・依存の追加はない。戦闘と図鑑は同じ造形を使う。敵の行動・能力・命中・床・保存データは変えない。

- `src/game/awakening.ts`：六段階覚醒の対象・移行・効果定義。召喚は `roster.ts` が重複時のみ更新する。UIは定義から表示し、通常戦闘は出撃時スナップショットを共通ステータス計算に加算する。正規化された対戦・レイドの `houndBonus` には混ぜない。

### 描画キャッシュ（2026-10-19）
- `three-world.ts`：背景専用メッシュを追加。背景はステージ変更時にだけ更新する。固定・動的バッファは必要容量を確保し、容量内はgeometryを破棄せず再利用する。
- `legacy-game.js`：表示中の画面に描画を限定。背景はレイアウト参照、床形状はレイアウトと表示用明るさ配列で無効化し、カーソルや移動範囲はキャッシュ外で生成する。判定は既存の共通ルールを使う。
- `mesh-builder.js`：待機中モデルのローカル形状を上限96件で再利用。形状に関係するキャラ・装備・属性・明るさ等をキーに含め、姿勢・被弾色・透過はインスタンスごとに適用。歩行・開口・竜・喰らいの時間変形はキャッシュ対象外。

### 表面材質（2026-10-19）
- `render/surface-textures.ts` が自作の石・木・土・金属アトラスを初回に生成し共有する。静的メッシュ専用のシェーダー拡張がワールド座標投影で色・高さを読み、粗さと微細な法線変化を適用する。キャラクター用マテリアルには適用しない。
- 既存の11要素／頂点を維持。glow属性の負値1〜4を材質IDとし、正値の発光とは分離。発光値は0以上に制限する。木箱は処理後に元の材質タグを復元する。
- テクスチャはMipMap付きの1枚だけ。ポリゴン増加や追加描画パス、フレームごとのノイズ生成は行わない。アトラスの全体サイズは1MiB、ミップ込み約1.33MiB。

### 四枠の技定義（2026-10-19）
- `game/battle-kit.ts` に猟犬ごとの専用技2枠、開始チャージ、基本連携対象、箱の移動先判定を配置する。UIと実行可能性は同じ割当を参照。攻撃技の範囲・威力は `hound-skills.ts` を引き続き使い、古い独立した猟犬→攻撃技割当を削除する。
- `legacy-game.js` の基本攻撃プレビューと実行は `basicDamage` を共有する。挟撃対象なら既存の連携アニメーションに置換し、独立した挟撃ボタンを生成しない。箱を移す前のプレビューは元の箱配列を復元し、判定用の確定状態へ漏らさない。

### 敵モデルの外装と材質（2026-10-19）
- `enemy-regalia.js`：種族ごとの低ポリゴンの面頬・肩甲・仮面・冠など。`enemy-detail.js` 経由で戦闘と図鑑が同じ形状を使う。
- 敵モデル生成の末尾で、変形／被弾色の適用前に骨・革・皮膚・金属の材質タグを付与。正の発光値は上書きしない。既存の11要素／頂点と待機形状キャッシュを維持する。
- キャラクター材質でも共有アトラスのシェーダーを有効化。材質タグ0の猟犬に表面の色・凹凸は加算しない。描画パスや新規画像メモリは増やさない。

- 図鑑の敵一覧は `hound-preview.ts` の共有コンテキストで静止画を生成し、`ui/expansion.ts` のIntersectionObserverで表示付近のみ遅延生成する。敵画像は種族・属性・ボスのキーで再利用し、UI再構築時に古いObserverを切断する。
- `model-framing.ts` は静止画と詳細ビューの中心・半径・必要幅の計算を共有する。`model-viewer.ts` は複数ポインタの距離を倍率へ、1ポインタの横移動を向きへ反映し、要求されたフレームだけ描画する。

- 図鑑の360度上下回転は `model-viewer.ts` のカメラ軌道で実装。モデルと包囲球は開く時に一度だけ構築し、`HoundWorld.redraw()` はアップロード済みの形状を再描画する。通常の戦闘は従来どおり `draw(vertices)` を使う。図鑑の影はモデルと光源が固定なので初回のみ計算する。
